# SenseNet 🔊

**Real-Time Assistive Sound Alert System for Individuals with Hearing Loss**

> Built by **Rivrr Tech** — College Hackathon, Hardware Track, 8 Hours

---

## What is SenseNet?

SenseNet is a wearable AI-powered alert system designed for people with hearing loss. When a hearing aid comes off — during sleep, rest, or any quiet moment — the person is completely cut off from their sound environment. There is no fallback. No second channel. Just silence.

SenseNet fixes that.

A web app on a phone continuously listens for dangerous sounds. When a potential threat is detected, it activates the camera to visually confirm the danger is real — not a false alarm. If confirmed, it sends a signal over Bluetooth to an ESP32-based wristband that wakes the user through vibration, LED alerts, and a text display showing exactly what triggered the alert.

---

## The Problem

- **70M+** people with hearing loss sleep without any sound awareness system
- Hearing aid users are completely isolated from their environment the moment the device comes off
- Existing solutions (light flashers, vibrating clocks) are fixed to buildings, handle only one job, and don't travel with the person
- Threshold-based decibel systems can't distinguish a door slam from a fire alarm — false alarms destroy trust

## How It Works

```
Microphone (continuous)
        ↓
TensorFlow.js + YAMNet — classifies sound on-device
        ↓
Potential danger detected?
        ↓ YES
Camera activates — captures single frame
        ↓
Audio + visual analyzed together (dual-confirmation)
        ↓
Confirmed real danger?
        ↓ YES
Bluetooth signal → ESP32
        ↓
Wristband alerts: Vibration + LEDs + LCD display
```

The **dual-confirmation layer** is what makes SenseNet different. Sound alone triggers false alarms. SenseNet listens first, then looks — only alerting when both sensors agree.

## Hardware

| Component | Purpose |
|-----------|---------|
| ESP32 Microcontroller | Receives Bluetooth commands from phone, controls all output components |
| Vibration Motor | Physical alert — fast pulse for high priority, slow pulse for low priority |
| NPN Transistor | Drives the motor safely from ESP32 GPIO |
| Flyback Diode | Protects circuit from back-EMF generated by the motor |
| Resistor | Limits base current into the transistor |
| 2x Red LEDs | Rapid blink for high-priority alerts (fire, crash, emergency) |
| 2x Green LEDs | Slow pulse for low-priority alerts (knock, doorbell, voice) |
| JHD16A LCD (16x2) | Displays alert type and priority level in text |
| 3.7V Battery | Powers the wristband unit |

## Features

### 🔴 LED Priority System
Two red and two green LEDs provide instant colour-coded urgency signalling at the hardware level — no software delay.

- **Red LEDs** — rapid blink for emergencies (fire alarm, loud crash, breaking glass)
- **Green LEDs** — slow pulse for attention alerts (knocking, doorbell, voice, phone ring)

### 📳 Priority Vibration Patterns
- **Fast vibration** — high priority danger, wake up immediately
- **Slow pulse** — low priority notification, someone needs your attention

### 📟 JHD16A LCD Watch Display
The 16x2 LCD shows exactly what triggered the alert and its priority level in real time:
```
FIRE ALARM      
Priority: HIGH!!
```
```
KNOCK DETECTED  
Priority: LOW   
```

### 🔍 Find My Watch
A button in the web app sends a Bluetooth command to the ESP32. All four LEDs blink rapidly and the LCD displays `FIND ME` — letting the user or a caregiver locate the wristband quickly.

### 🧠 On-Device AI Classification
TensorFlow.js + YAMNet runs entirely in the browser. No server, no cloud, no latency. YAMNet is pre-trained on 521 sound classes including fire alarms, knocking, speech, and more.

### 📷 Camera-Based Visual Confirmation
Before any alert fires, the phone camera captures a frame and analyzes it alongside the audio clip. Real threats are confirmed. False alarms are filtered out.

## Tech Stack

| Technology | Why We Chose It |
|------------|----------------|
| **ESP32** | Dual-core MCU with built-in Bluetooth. Handles BLE communication, PWM motor control, GPIO for LEDs, and I2C for LCD simultaneously — at an unbeatable price point |
| **TensorFlow.js + YAMNet** | Runs entirely in the browser — zero installation, zero cloud dependency, zero latency. Pre-trained on 521 sound classes |
| **JavaScript Web App** | Browser-based means no app install needed. Accesses mic and camera APIs natively, sends Bluetooth commands to ESP32 via Web Bluetooth API |
| **JHD16A LCD (16x2)** | Simple, low-power I2C display. Two full lines of text is enough to show alert type and priority. Wires directly to ESP32 with 4 pins |
| **NPN Transistor + Diode** | Standard motor driver circuit — protects ESP32 GPIO while enabling full motor current. Textbook reliable |

## Circuit Overview

```
ESP32 GPIO (PWM)
      |
   Resistor (base limiting)
      |
   NPN Transistor
      |           |
   Motor (-)   Diode (flyback protection)
      |           |
   Battery (+) ──┘
```

**LED Wiring:**
- Red LED 1 + Red LED 2 → GPIO pins with current-limiting resistors → GND
- Green LED 1 + Green LED 2 → GPIO pins with current-limiting resistors → GND

**LCD Wiring (JHD16A — I2C mode):**
- SDA → ESP32 GPIO 21
- SCL → ESP32 GPIO 22
- VCC → 3.3V
- GND → GND

## Getting Started

### Prerequisites
- ESP32 development board
- Arduino IDE with ESP32 board package installed
- A smartphone or laptop with a modern browser that supports Web Bluetooth API (Chrome recommended)
- Bluetooth enabled on both devices

### ESP32 Setup
1. Clone this repository
2. Open `esp32/sensenet_wristband.ino` in Arduino IDE
3. Upload to ESP32
4. Open Serial Monitor — ESP32 will begin advertising over Bluetooth

### Web App Setup
1. Open `webapp/index.html` in Chrome
2. Click **Connect to Wristband** and pair with the ESP32 via Bluetooth
3. Grant microphone and camera permissions
4. Click **Start Monitoring**
